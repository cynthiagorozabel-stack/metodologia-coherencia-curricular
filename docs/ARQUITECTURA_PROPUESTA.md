# Arquitectura y productos del antecedente metodológico

Este documento conserva el alcance conceptual del trabajo previo; las capas descritas no se presentan como software implementado. El código que existe en este repositorio genera y comprueba demostraciones sintéticas.

## Secuencia de productos

Gobernanza transversal → modelo conceptual → caracterización de fuentes → especificación de indicadores → reglas de integridad y límites de cálculo → modelado de dominio → revisión de preparación → diseño operativo → especificación de implementación.

El diseño de base de datos planteaba asignatura, versión de sílabo, acta y análisis cualitativo macro-micro. La trazabilidad debe conservar documento, localizador, evidencia textual, interpretación propuesta, revisión humana y dependencias pendientes. No se necesita una base de datos desplegada para utilizar las fichas.

## Separación de responsabilidades

1. Ingesta documental: extraer texto y metadatos, verificando columnas y símbolos.
2. Análisis semántico: proponer interpretaciones con evidencia, sin convertir palabras en niveles automáticos.
3. Integridad de registros: comprobar rangos y sumas sin reconstruir notas ausentes.
4. Revisión humana: confirmar, corregir o rechazar juicios y registrar fundamento.

Estados operativos del diseño previo: AVAILABLE, AVAILABLE_WITH_NOTICE, REVIEW_REQUIRED, NOT_CALCULABLE y PROCESSING_FAILED. Un aviso metodológico no debe transformarse en una nota o un dictamen estudiantil. No se atribuye a estos estados una validación de interfaz ya ejecutada.

## Alcance consolidado

La proyección contrafactual numérica OPCP formó parte del antecedente, pero la autora fijó posteriormente el análisis vigente en interpretar datos obtenidos sin promedios ni reponderación. No se publica como resultado vigente una simulación de cambio de pesos. El ejemplo ampliado de este repositorio es un diseño alternativo ficticio de registro, no OPCP ni una predicción causal.

IDCD, CSRA e IRPC se mencionan como nombres del antecedente: las fichas operativas no se hacen pasar por versiones numéricas validadas de esos índices. La correspondencia macro-micro sigue siendo cualitativa. La puerta READY_WITH_CONDITIONS del antecedente no reemplaza la validación pedagógica y no convierte este repositorio en una plataforma de acreditación.
